# 냉로그

**구매 기록을 재고로 바꾸고, 오늘 먼저 사용할 재료를 알려주는 냉장고 관리 웹앱.**

식재료를 기록하고 수량을 계속 맞추는 번거로움을 줄이는 것이 핵심이다. 기능 목록보다 구매 → 확인 → 보관 → 브리핑 → 실제 소비 흐름을 우선한다.

## 지금 체험할 수 있는 것
- 로그인 없는 브라우저별 기본 데모 재고와 오늘의 브리핑
- 직접 입력 구조화, 영수증/온라인 캡처 선택과 이미지 미리보기
- 모의 분석 결과의 이름·수량·단위·구매일·보관 수정 및 등록
- 냉장·냉동·실온 필터, 상세, 수량 조정, 소비·폐기 기록
- 자연어 요청 해석과 실행 전 확인
- 저장·새로고침 복원 및 데모 초기화

**현재 외부 AI API와 실제 OCR은 연결하지 않았다.** 이미지 분석은 사진과 무관한 샘플 4개를 보여주며 화면에 이 한계를 표시한다. 텍스트와 명령은 규칙 기반이다. 예상 사용 시점도 검증 전 데모 정책이며 식품 안전 판단으로 사용할 수 없다.

## 데모 순서
1. 홈에서 버섯 우선 브리핑 확인.
2. 구매 추가에서 이미지 선택 → 예시 분석 → 수량 수정 → 등록.
3. 동일 이름 구매가 중복되면 상세에서 특정 재고 선택. 기본 데모 상태에서는 도우미에 “계란 3개 썼어” 입력 → 확인 → 7개.
4. “닭가슴살 냉동으로 옮겼어” 입력 → 확인 → 보관/예상 시점 변경.
5. 기록 확인 후 새로고침하여 재고 유지 확인.
6. 기록 화면에서 데모를 초기화해 다시 체험.

## 기술 및 구조
React 19, TypeScript, Vinext/Vite, Shadcn(Base UI), Sites/Cloudflare Workers.
UI → Mock AIProvider → 도메인 검증/계산 → localStorage 스냅샷.
구매·재고·분석·거래 데이터를 분리하고 수량과 원장을 함께 저장한다. 서버 DB, 기기 간 동기화, 실제 AI 및 업로드 저장은 미구현이다. 이미지 원본은 브라우저를 떠나지 않는다.

## 실행
Node 22.13 이상과 npm 필요.
```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run lint
npm run build
```
`lint`는 직접 작성한 코드 대상이다. `lint:all`은 공식 템플릿의 모든 UI 파일까지 검사하며 미사용 vendored 컴포넌트의 기존 경고도 보고한다.
Windows 내장 런타임을 사용하는 환경의 실행 경로는 RESUME_STATE.md를 확인한다.

## 검증과 한계
도메인 시나리오 테스트는 수량/날짜/중복/모호한 대상/저장 실패를 검증한다. 브라우저 클릭 기반 E2E와 스크린샷 검증은 아직 수행하지 않았다. 공용 심사용 URL은 배포 및 접근 정책 검증 후 기록한다. 현재 문서는 최종 대회 제출 완료 선언이 아니다.

## 주요 결정
- 외부 AI 없는 단계에서도 구매에서 소비까지 이어지는 구조부터 완성.
- 모의 결과를 실제 인식 결과로 오인하지 않도록 출처 표시.
- 숫자·날짜·거래 처리는 일반 코드에서 수행.
- 회원가입 없이 방문자별 로컬 데이터로 즉시 데모 가능.
- 같은 이름 구매는 합치지 않고 별도 로트로 유지. 자연어로 모호하면 상세 화면에서 선택.

제품 범위는 PROJECT.md, 동작 조건은 PRODUCT_SPEC.md, 향후 AI 연결은 AI_PROVIDER_SETUP.md를 참고한다. 다음 단계는 실제 브라우저 시나리오, 서버 DB, 정책 근거 검토와 대회 제출 자료 보강이다. 실제 AI는 사용자 허가 이후에만 연결한다.
