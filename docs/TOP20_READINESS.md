# 제출 준비 체크리스트 · 2026-09-12

사용자가 제공한 네 가지 평가 항목을 기준으로 정리했다. 대회 공식 규정/배점은 검증하지 않았으며 TOP20 진출을 보장하지 않는다.

| 항목 | 이번 구현 | 남은 검증 |
|---|---|---|
| 기획력 | 영수증 입력→식품 확인→재고→오늘 브리핑 연결 | 실제 사용자 입력 시간/수정 비율 측정 |
| 실현 가능성 | 촬영/업로드 공통 경로, D1 저장, 오류/가격 분리/등록 검증 | 실기기 카메라, 흐림·비영수증 인식 |
| 확장성 | 공통 Provider, ProductExplorer, optional 메타데이터로 구형 DB 호환 | 외부 검색 과금 합산/메타데이터 근거 계약 |
| AI 활용 적절성 | 음식/비음식/애매함 분리, 후보 확인, 원본/의미/신뢰도 보존 | 실제 OCR/Vision/검색은 미연결; Mock과 구분 표시 |

## 구현 순서와 변경 파일

기존 app/page.tsx의 업로드/상품 수정, src/ai.ts의 Mock, domain/validation/schema를 확장했다. 신규 파일은 app/receipt-input.tsx, app/receipt-review.tsx, src/receipt-resolution.ts다. 대규모 프레임워크 변경이나 DB 재작성은 하지 않았다.

## 시연

홈의 촬영 또는 업로드 → 이미지 선택 → 예시 분석 → 식품4개 확인/휴지 제외/서울1000 후보 확인 → 수량·보관·제품 표시 날짜 수정 → 확인하고 일괄 등록 → 홈 우선순위. 현재 이미지 내용은 읽지 않는 고정 Mock임을 첫 단계에서 밝힌다. 실제 AI 성능을 입증하는 데모로 제출하지 않는다.

텍스트 검증 예: 서울우유 나100% 1L / 비비고 왕교자 1봉 / 대패삼겹살 600g / 휴지 1개 / 서울 1000 / 참P 500. 후보 없는 냉동A·행사상품1은 확정하지 않는다. 가격3,000원은 수량으로 등록하지 않는다.
